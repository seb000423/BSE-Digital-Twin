## 1. 디자인 원칙
1. **정밀함**: 산업 장비처럼 정렬과 간격이 정확하게
2. **절제**: 남색 청사진 한 가지 색조, 장식보다 정보
3. **신뢰**: 장난감 같지 않은 B2B 산업 소프트웨어 톤
4. **움직임은 의미 있게**: 공정을 떠올리게 하는 움직임만 ([09 3D 가이드](09_3D_VISUAL.md))

### 2.1 로딩 화면 문구 규칙 (D-28, D-29)
게임 엔진·3D 앱의 관례는 로딩 단계를 **작업의 종류**로만 부릅니다 (예: Initializing / Loading assets / Compiling shaders / Loading world / Preparing). 파일 이름, 글꼴, 라이브러리, 서버 주소 같은 **기술 내용은 화면에 적지 않습니다** (기술 유출 + 사용자에게 무의미). 우리 규칙:

| 규칙 | 내용 |
|------|------|
| 형식 | `페이지 이름 — 작업 종류 — %` 한 줄 (D-26). % 는 꾸민 값이 아니라 실제 받은 양 (D-27) |
| 문구 | "OO 로딩 중" 꼴의 **포괄적인 작업 종류**만. 세부 항목(어떤 glb, 어떤 폰트)은 금지 |
| 개수 | 한 화면에 3~5단계. 더 쪼개지지 않게 |
| 꾸민 단계 금지 | "마무리 중", "거의 다 됐어요" 같이 실제 작업이 없는 문구는 넣지 않음. 100%가 되면 마지막 실제 작업 문구가 남은 채 사라짐 (D-28) |
| 실패 | 실패해도 기술 이유를 적지 않고 "불러오지 못했습니다 — 다시 시도" 수준으로 |

**작업 종류 어휘 (여기 있는 말만 씀)**

| 한국어 | 영어 | 뜻 (내부 기준, 화면에는 안 적음) |
|--------|------|----------------------------------|
| 초기화 중 | Initializing | 아직 아무 파일도 안 도착했을 때, 앱 시작 |
| 구성 로딩 중 | Loading setup | 화면 구성 요소: 스타일, 글꼴, 설정, 레이아웃 |
| 에셋 로딩 중 | Loading assets | 3D 엔진·모델·텍스처·블록 라이브러리 등 큰 파일 |
| 화면 준비 중 | Preparing view | 받은 것으로 첫 화면·3D 장면을 그리는 중 (랜딩, 빌더 뷰포트) |
| 시뮬 로딩 중 | Loading simulation | 시뮬레이션 엔진·시나리오 준비 (빌더 실행 모드에서만) |
| 연결 중 | Connecting | 서버·현장 게이트웨이 접속 (Monitor) |
| 데이터 로딩 중 | Loading data | 저장된 설비·공장 데이터, 실시간 값 (Monitor) |

현재 적용: 랜딩 첫 로딩은 구성 → 에셋 → 화면 준비 (loader.js). "시뮬 로딩 중"은 실제 시뮬레이션이 뜨는 화면에서만 씀 (오너 지적 2026-11-02). Build/Monitor 화면도 같은 어휘를 씀.

## 9. 앱 화면 규칙 (BSE Studio, 2026-11-02 확정, D-34)
오너가 확정한 시제품(홈 · 설비 편집 · 공장 실행 화면에 3D 장면을 넣은 클릭형 데모)이 기준입니다. 앱 화면을 만들 때 아래를 지킵니다.

### 9.1 한 가지 모습
- 랜딩과 **같은 색·글꼴·모서리(2px)** 를 그대로 씀 (4·5장 변수). 테마는 하나, 라이트/다크 전환 없음.
- 화면 글은 한국어. 태그 이름, 3D 이름표, 태그라인(Build · Simulate · Evolve)만 영어.
- 태그·치수·시각·지표 숫자는 고정폭 글꼴, 숫자는 오른쪽 정렬.

### 9.2 상태 색 3가지 (앱에서만)
| 뜻 | 값 | 쓰는 곳 |
|----|----|---------|
| 가동 · 확인됨 | `#5ad28a` 초록 | 점, 테두리, 글자 |
| 대기 · 경고 · 미확인 값 | `#f5b942` 노랑 | 점, 테두리, 글자 |
| 알람 · 충돌 | `#ff6b6b` 빨강 | 점, 테두리, 글자 |

면을 채우는 데는 쓰지 않음(막대 그래프의 띠만 예외). 그 밖의 강조색은 없음.

### 9.3 화면 뼈대
- **홈** (2026-11-02 고침, D-37): 제목 줄(BSE Studio + 한 줄 길잡이 "만들고 → 돌려 보고 → 현장과 맞춘다" + 오른쪽 `저장한 설비 열기`) → **설비** 패널(템플릿 3종 카드 3열, 위에서 본 그림, 머리글 오른쪽에 `+ 새 설비`) → **공장** 패널(표, 머리글에 `+ 새 공장`)과 **최근 실행** 패널(표, 머리글에 `Simulate 열기`). 새로 만들기 버튼은 제목 줄이 아니라 각 패널 머리글에 하나씩. 카드·행은 모두 눌러서 그 화면으로 이어짐.
- **머리 메뉴**: Studio(홈) · **Build = Machine | Factory**(작은 "Build" 글자 뒤에 두 링크, 2026-11-04 D-42) · Simulate · Evolve. 전부 화면이 있어야 하며 "준비 중"으로 막힌 메뉴를 두지 않음. 아직 없는 기능은 그 화면 안에서 무엇이 들어올지 적는다.
- **편집기**(설비·공장 같은 틀, 다른 페이지): 위 작업줄 → 왼쪽 팔레트·트리 → 가운데 3D 뷰포트 → 오른쪽 속성 → 아래 신호 표/수동 조작/지표. 모드 전환(편집·실행·비교)은 랜딩 KR/EN 토글과 같은 모양. **실행** 을 누르면 바로 움직여야 한다(RUN·START 류 태그를 켜고, 동작 순서가 있으면 자동 운전까지 — `startDemo`). 아무것도 안 움직이는 실행 모드는 없다.
- **팩토리 빌더**(2026-11-04, D-42): 왼쪽 = `건물 (외형)`(이름·가로·세로·처마 높이·기둥 간격 → `건물 다시 올리기` / `새 공장`) + `설비 카드 (내부)`(누르면 놓임) + `놓인 설비` 목록. 가운데 = 공장 3D(설비 끌어 옮기기 100 mm, 벽·기둥·문 클릭 선택, `지붕 얹음/걷음`, X-ray). 오른쪽 = 선택한 것의 속성(설비: 위치·회전 90° 단추·태그 접두어·참조·카드 / 벽: 길이·높이·개구부 목록 + `문 내기` / 문·기둥·바닥). 아래 = `설비 표` · `흐름`(출발 → 도착 고르고 `잇기`, `끊기`) · `명령 기록`.
- **패널 구분**(2026-11-04, D-41): 패널 머리글은 왼쪽 앰버 표식(3 × 12px) + 패널색 바탕 + 굵은 글자. 옆·아래 패널 바탕(`.pane`)은 가운데 3D 보다 한 단 밝게. 패널이 "눈에 안 들어오면" 안 된다.
- **아래 패널 = 신호 표 + 동작 순서 + 수동 조작·명령 기록** (2026-11-03, D-40). 신호 표 칸: 블록 · 태그 · **뜻**(한국어, 태그 이름 조각으로 자동) · **종류**(명령 = 우리가 켜고 끔 / 상태 = 설비가 알려 줌, 수치면 표시) · 연결 · 값. 설비를 만드는 화면이므로 **설비 자체의 동작 실험**이 되어야 한다: `동작 순서` 패널에 스텝 목록(현재 스텝 강조, 켜는 태그·조건·기다림 표시)과 단추 `▶ 자동 운전/■ 멈춤` · `자동 만들기` · `↺ 워크`. 자동 운전은 실행 모드가 아니면 실행부터 켠다. 순서는 machine.json 의 `sequence` 에 저장된다.
- 모든 칸은 **같은 패널**(테두리 1px + 제목 줄 44px + 안쪽 여백 16px). 칸마다 다른 모양을 만들지 않음.
- 화면당 채워진(밝은) 버튼은 **하나**(홈 `새 설비`, 편집 `저장`, 실행 `정식 실행 보내기`).

### 9.4 3D 뷰포트
- 차콜 바닥 격자(1 m) 위에 설비를 **옅게 채운 면 3단계(#2b2a26 · #3b3933 · #514d45) + 베이지 외곽선 #d8cfbd**으로 그림 (2026-11-04 D-41, 남색 대체). 메이커 CAD 모양을 흉내 내지 않음.
- **보기 두 가지 = 면 ↔ X-ray** (2026-11-04, D-42): 뷰포트 왼쪽 아래 토글. X-ray 는 면을 완전히 비우고 외곽선만 남겨 벽 너머·설비 속까지 보임(선 진하기로 앞뒤 구분). Machine·Factory·Simulate 공통. 은선 선화(뒤를 가리는 선화)는 쓰지 않음.
- 선택 = 흰색 외곽선. 이름표 = 태그 접두어(영어, 굵게) + 이름, 작은 테두리 상자. 자재 흐름 = 실선, AMR 동선 = 초록 점선.
- **Simulate 보기 = 실사풍 '차콜 + 베이지 + 앰버'** (2026-11-04 D-41; 2026-11-03 D-39 의 그래파이트+블루를 대체, 설정값은 그대로): 설비는 따뜻한 회색·베이지 3단계(#35332e · #8e877a · #d6ccb9) PBR 면, 강조는 앰버 #ffb14a 한 색(워크·발광체·링·흐름 빛). 배경 #1a1917, 바닥 #221f1b, 키라이트 #fff1dc. 직교 아이소메트릭(1,1,1)에서 시작, 끌어서 돌림(자동 회전 없음). 조명 = 아이보리 키라이트 3(그림자 2048) + 림 0.6 + 앰비언트 0.08, 환경광 0.85, 톤매핑 Neutral 노출 0.95. 바닥은 원형으로 배경에 녹이고 격자(1 m·5 m)는 바닥 셰이더 안에서 그림(별도 격자 메시 없음 → 깊이 싸움 없음). 블룸은 임계 2·강도 0.45 로 발광 재질에만. 외곽선은 선택 때만. **연출**(참고 장면의 기법을 우리 코드로): 바닥 거울 반사(아주 약하게, 반투명 반사 면 한 겹), 지금 보는 설비 밑 발광 링(숨쉬듯), 가동(RUN) 중인 컨베이어 위를 흐르는 작은 빛 조각(방향 DIR 반영), 타워램프 R·Y·G 와 센서 ON 이 켜지면 그 도형이 발광. 전부 런타임 신호만 읽는다. 은선 선화('lines')는 코드에 남겨 두되 화면에선 쓰지 않음. Build 는 그대로 옅게 채운 면(클릭·끌기용).
- 랜딩의 네이비 테마와 스튜디오의 차콜 테마는 **역할이 다르다**: 랜딩(입구)은 네이비 그대로, 스튜디오(작업 공간)는 패널·단추·3D 전부 차콜·베이지·앰버(2026-11-04 오너: "네이비로 맞추지 말고 저 느낌 그대로"). 참고 화면에서 가져온 것은 **느낌과 설정값**뿐, 색 코드·모델·문구는 우리 것(D-31).
- 깊이 싸움 방지: 외곽선(Line2 삼각형 띠)을 polygonOffset 으로 면보다 살짝 앞에 그리고, 바닥 격자는 바닥면보다 20 mm 아래, 카메라 near/far 를 설비 크기에 맞춰 짧게(깊이 정밀도), 기울기는 최대 79°. 가림막 면 자체는 밀지 않는다(밀면 격자와 겹쳐 회전 시 깜빡임).
- 실행 조작은 **재생 · 정지 단추 둘 다 항상 보이고**, 배속은 가로 바(×1~×10, 실행 중 즉시 반영). 화면 이동 단추("Build 에서 편집 →")는 세로 선으로 떼어 놓는다.
- 아래 패널(신호 표 · 수동 조작/명령 기록)은 위쪽 손잡이로 높이 조절(120px~화면 70%, 브라우저에 기억), `접기` 단추, 두 칸 사이 세로 손잡이로 너비 조절.
- 블록 끌어서 옮기기: 누른 채 끌면 그 높이의 수평면 위에서 50 mm 단위로 움직임. 빈 곳 끌기 = 화면 회전, 휠 = 확대.
- 실행 모드에서 지금 보는 설비는 바닥 고리로 비추고, 설비·목록을 클릭하면 그 설비로 이동. Build 실행 모드에서도 컨베이어 흐름 빛과 상태등·센서 발광은 켜진다(동작 실험이 눈에 보이게).
- 편집기의 모든 조작은 **명령**으로 남김(`add_block`, `set_param`, `force_tag` …, [14 편집 명령](14_EDIT_COMMANDS.md)). 화면은 명령을 부르기만 함.

### 9.5 하지 않는 것
- 소개 문구·장식 그림·그라데이션 버튼. 로딩 문구는 2.1절 어휘만.
- 다른 회사 제품 화면(저채도 저폴리 입체 등)을 베끼지 않음 (D-31).
