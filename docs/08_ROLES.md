## 1. 리드 프로덕트 디자이너 (UI/UX) — 약칭 `PD`

- **영문 직함:** Lead Product Designer (UI/UX)
- **이 이름인 이유:** 요즘 IT 회사에서 화면 설계, 사용 경험, 브랜드까지 맡는 디자이너를 부르는 표준 직함. '웹 디자이너'보다 넓게 제품 전체의 화면을 책임진다는 뜻. '리드'는 최고 결정권자 수준.

**한 줄 정의:** 첫 화면 3초 안에 "제대로 만든 산업용 제품"이라는 인상을 주는 사람.

**책임 (주)**
- 레이아웃, 여백, 타이포그래피, 색, 버튼, 반응형(휴대폰/PC)
- 브랜드 일관성: 제품명 표기, 삼각형 B/S/E 로고, beta 표기, KR/EN 문구
- 화면 속도와 접근성 (느린 기기, "움직임 줄이기" 설정)

**판단 기준**
- 덜어낼 수 있으면 덜어낸다. 남색 청사진 한 가지 색조, 장식보다 정보
- 장난감 같지 않고, 신뢰감 있는 B2B 산업 소프트웨어 톤
- 애니메이션은 글자와 버튼을 가리지 않는다

**검토 (부)**: 3D 연출이 화면 구성·가독성을 해치지 않는지

**산출물**: [04 디자인 가이드](04_DESIGN_GUIDE.md), 랜딩 페이지 화면

## 2. 3D 테크니컬 아티스트 리드 — 약칭 `TA`

- **영문 직함:** Lead Technical Artist, Industrial 3D Visualization
- **이 이름인 이유:** 3D를 예쁘게 만드는 감각과 실시간으로 가볍게 돌아가게 하는 기술을 함께 가진 사람을 업계(게임·디지털 트윈·Three.js)에서 '테크니컬 아티스트'라고 부름. 산업 공장 시각화가 전문 분야.

**한 줄 정의:** 실제 공장을 아는 눈으로, 화면 속 3D가 "진짜 공장의 질서"처럼 보이게 만드는 사람.

**책임 (주)**
- 3D 배경·장면 연출: 설비 형태, 선, 카메라, 재질, 움직임
- 공장의 시각 언어 반영: 격자(그리드) 배치, 라인(컨베이어) 흐름, 모듈 단위 조립, 정밀한 정렬
- 성능 예산: 일반 노트북과 휴대폰에서 끊기지 않게 (개수, 그림자, 효과 조절)

**판단 기준**
- 움직임에는 "공정 같은 이유"가 있어야 한다 (예: 클릭하면 공장이 층층이 열려 안을 보여줌)
- 부드럽게 튀는 효과보다 기계적인 정확함 (등속 이동, 딱 맞물림, 스냅)
- 회색 계열 산업 재질, 과한 빛번짐·네온 금지

**검토 (부)**: 웹 디자인이 3D 공간감을 살리는지, 아키텍처 그림이 실제 공장 구조와 맞는지

**산출물**: [09 3D 비주얼 가이드](09_3D_VISUAL.md), 배경 애니메이션(bg.js)

## 3. 스마트제조 수석연구원 — 약칭 `MR`

- **영문 직함:** Principal Researcher, Smart Manufacturing (Industry 4.0)
- **이 이름인 이유:** 국내 연구소·대기업에서 실제로 쓰는 명칭. '스마트팩토리'는 공장 자체를, '스마트제조'는 공장 운영 방식과 표준(AAS, ISA-95)까지 포함하는 연구 분야 이름.

**한 줄 정의:** 이 제품이 실제 공장에서 쓸모 있는지, 업계 표준에 맞는지 책임지는 사람.

**책임 (주)**
- 제품의 목적, 대상 사용자, 기능 범위, 우선순위
- 기준서 지킴이: 설계 원칙 7개, 데이터 모델(machine.json / factory.json), 범위(V1/V2/V3)가 흔들리지 않게
- 산업 표준과 기술: ISA-95(공장 계층), AAS/AASX(변환 기능), DES(처리량·병목 계산)
- 용어를 정확하게, 그러면서 쉽게

**판단 기준**
- "현장 운영자가 실제로 쓰는가?"
- 특정 회사 장비에 묶이지 않는 표준 기반
- 눈에 보이는 연출도 실제 디지털 트윈 개념(실물 ↔ 가상 동기화)을 왜곡하지 않는다

**검토 (부)**: 3D·웹 연출이 디지털 트윈 개념을 정확하게 표현하는지

**산출물**: [01 개요](01_OVERVIEW.md), [02 요구사항](02_REQUIREMENTS.md), [03 아키텍처](03_ARCHITECTURE.md), [07 용어집](07_GLOSSARY.md)

## 4. OT 통합 엔지니어 — 약칭 `OT`

- **영문 직함:** OT Integration Engineer (Industrial Networks)
- **이 이름인 이유:** OT(Operational Technology, 운영 기술)는 공장 설비 쪽 기술을 IT와 구분해 부르는 말. 설비 통신(OT)과 회사 시스템(IT)을 이어주는 사람을 현장에서 이렇게 부름. 비슷한 직함: 제어 시스템 통합(SI) 엔지니어.

**한 줄 정의:** 실제 공장 설비와 디지털 트윈 사이의 데이터가 정확하고 안전하게 오가도록 책임지는 사람.

**책임 (주)**
- 태그(신호) 이름 규칙과 신호 테이블 (기준서 4.4절): 시뮬레이션과 실제 PLC가 같은 이름을 쓰도록
- 좌표·단위 규약 (기준서 5장)과 I/O 리스트 엑셀 표준 양식
- 현장 연결(V2): Node-RED·rosbridge 게이트웨이 구성, 수집 주기, 아웃바운드 전용 원칙
- 통신 보안: 읽기 전용 원칙, 태그 쓰기 기본 비활성, 네트워크 분리 (기준서 11장)

**판단 기준**
- 현장 설비를 절대 방해하지 않는다 (읽기 우선, 과도한 요청 금지)
- 끊겨도 복구된다 (재연결, 값 품질 표시, 시간 기록)
- 특정 제조사에 묶이지 않는 표준 우선

**검토 (부)**: 요구사항과 아키텍처가 실제 현장 통신으로 구현 가능한지

**산출물**: [03 아키텍처](03_ARCHITECTURE.md)의 데이터 연결 부분, 통신 사양 문서 (예정)

## 5. 로보틱스 시뮬레이션 엔지니어 — 약칭 `RS`

- **영문 직함:** Robotics Simulation Engineer (NVIDIA Omniverse / Isaac Sim / Isaac Lab)
- **이 이름인 이유:** Omniverse·Isaac 기반 일을 하는 사람을 NVIDIA 생태계와 로봇 회사 채용 공고에서 부르는 일반적인 직함. 도구 이름은 괄호로 전문 분야를 밝힘.

**한 줄 정의:** 웹 시뮬레이션 엔진이 실제 설비처럼 움직이고 숫자(사이클타임)가 맞게 나오도록 책임지고, 나중에 Omniverse/Isaac으로 확장할 길을 열어 두는 사람.

**책임 (주)**
- 기준서 6장 머신빌더(관절·축·로봇 URDF)와 8장 시뮬 엔진(신호·기구학·DES·네비 4층)의 검수
- 동작 속도·가속도(vmax·amax)와 사이클타임 계산 규칙 (기준서 8.5절)
- Omniverse/Isaac 확장 준비 (D-21): JSON → USD/URDF 내보내기 규칙, 좌표 규약이 Omniverse와 맞는지
- V3: Isaac Sim 정밀 물리, Isaac Lab 로봇 학습, Sim-to-Real

**판단 기준**
- 보기 좋은 것보다 물리적으로 맞는 것 (속도, 가속도, 사이클타임). 미확인 값은 verified=false
- V1은 웹 엔진으로 끝낸다. 정밀 물리는 셀 단위로만, V3에서
- 같은 공장 데이터 하나로 웹 화면과 Omniverse가 함께 움직인다 (중복 모델링 금지)

**검토 (부)**: 3D 연출과 시뮬레이션 요구사항이 웹 엔진으로, 나중에 Omniverse/Isaac으로 실현 가능한지

**산출물**: Simulate 단계 설계, [03 아키텍처](03_ARCHITECTURE.md)의 시뮬레이션 부분
