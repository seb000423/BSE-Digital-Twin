## 제품
| 용어 | 쉬운 설명 |
|------|-----------|
| 디지털 트윈 | 실제 공장을 컴퓨터 안에 똑같이 만들고, 실제 데이터로 계속 맞춰지는 "쌍둥이" |
| Build | 가상 공장을 만드는 단계 (= 머신빌더 + 팩토리빌더) |
| Simulate | 가상 공장을 미리 돌려보는 단계 (= 시뮬레이션) |
| Evolve | 실제 공장 데이터와 시뮬 결과를 다시 설계에 반영해 발전시키는 단계 (= 디지털 섀도 + 최적화 피드백, V2). 이전 이름 Execute (D-30) |
| BSE Studio | 가상 공장을 만드는 빌더 프로그램 |
| Monitor | 공장 상태를 실시간으로 보는 화면 |
| 개발 기준서 | [11 BSE : Digital Twin 개발 지침서 R1](11_BSE_DT_DEV_STANDARD.md). 빌더 앱을 어떻게 만들지 정한 최상위 설계도 |

## 기준서 용어 (빌더·시뮬레이션)
| 용어 | 쉬운 설명 |
|------|-----------|
| 머신빌더 | 블록을 조립해 설비 한 대를 만드는 작업 공간 |
| 팩토리빌더 | 평면도 위에 벽·기둥을 그리고 설비를 배치해 공장을 만드는 작업 공간 |
| 블록 | 설비를 이루는 조립 부품 (프로파일, 실린더, 컨베이어, 센서 …). "형식 + 치수"이지 메이커 제품이 아님 |
| 소켓 | 블록끼리 딱 맞게 붙는 접속점. 끌어다 놓으면 스냅됨 |
| 관절 | 블록이 움직이는 축 (밀고 당기기, 회전) |
| 태그 | 설비 신호 하나 (예: `CYL1_FWD` = 실린더 1 전진). 시뮬과 실제 PLC가 같은 이름을 씀 |
| 신호 테이블 | 모든 태그의 현재 값을 모아 둔 표. 시뮬레이션의 네 층은 이 표로만 대화함 |
| 설비 카드 | 설비 한 대의 요약(사이클타임, 양품률, 크기, 투입/배출구). 공장에 놓을 때 쓰는 단위 |
| fidelity 등급 | 설비를 얼마나 자세히 만들었는지. L1 카드만 / L2 기구·신호 / L3 물리 |
| machine.json / factory.json | 설비 한 대 / 공장 하나를 저장하는 파일 형식 |
| 편집 명령(API) | "블록 추가", "값 설정" 같은 명령 단위. 화면도 AI도 이 명령을 부름 |
| DES | 이산사건 시뮬레이션. 설비를 하나하나 움직이지 않고 "언제 끝났다" 사건만으로 처리량·병목을 빨리 계산 |
| 네비 | 작업자·AMR·지게차가 바닥 마킹을 따라 길을 찾는 층 |
| 시나리오 | 공장 스냅샷 + 바꾼 값 + 실행 설정. 두 시나리오를 나란히 비교 |
| 헤드리스 실행 | 화면 없이 서버에서 시뮬레이션을 수백 번 돌리는 것 |
| 디지털 섀도 | 가상 PLC 대신 실제 태그로 화면이 움직이는 상태 (Monitor의 정식 이름, V2) |
| 게이트 | 다음 단계로 가기 전 통과해야 하는 검사 (기준서 V1에 2개) |
| V1 / V2 / V3 | 1차 판매 가능 제품 / 현장 연결·AI·로봇 / 학습형 AI·정밀 물리 |

## 공장 / 산업
| 용어 | 쉬운 설명 |
|------|-----------|
| 스마트팩토리 | 설비가 데이터로 연결되어 자동으로 관리되는 공장 |
| 라인 | 제품이 순서대로 거쳐가는 설비 줄 |
| 병목 | 라인에서 가장 느려서 전체 속도를 막는 지점 |
| 가동률 | 설비가 실제로 일한 시간의 비율 |
| PLC | 설비를 직접 움직이는 작은 제어 컴퓨터 |
| SCADA / HMI | 설비 상태를 보고 조작하는 감시 화면 |
| MES | 작업 지시와 생산 실적을 관리하는 시스템 |
| ERP | 주문, 재고, 회계 등 회사 전체를 관리하는 시스템 |
| ISA-95 | 공장 시스템을 층(현장 → 제어 → 감시 → 생산관리 → 경영)으로 나누는 국제 기준 |

## 표준 / 통신
| 용어 | 쉬운 설명 |
|------|-----------|
| AAS | 설비의 "디지털 신분증". 이름, 사양, 데이터를 담는 산업 4.0 국제 표준. 우리 제품에서는 저장 형식이 아니라 변환(가져오기·내보내기) 대상 (D-22) |
| AASX | AAS 정보를 담은 파일 |
| Node-RED | 여러 PLC 통신(OPC UA·Modbus·S7 등)을 받아 MQTT/WebSocket으로 바꿔 주는 외부 도구. 기준서가 직접 개발 대신 쓰기로 한 것 |
| rosbridge | ROS2(로봇 소프트웨어)와 웹을 이어 주는 외부 도구 |
| OPC UA | 공장 설비끼리 데이터를 주고받는 대표 표준 통신 방식 |
| Modbus | 오래되고 널리 쓰이는 단순한 설비 통신 방식 |
| MQTT | 센서 데이터를 가볍게 보내는 통신 방식 |
| Sparkplug B | MQTT로 공장 데이터를 주고받을 때 형식을 맞추는 규칙 |
| 태그 | 설비에서 읽어오는 신호 하나 (예: 모터 온도) |
| 게이트웨이 | 여러 설비의 통신을 모아 변환해주는 중간 장치/프로그램 |

## 시뮬레이션
| 용어 | 쉬운 설명 |
|------|-----------|
| NVIDIA Omniverse | 3D 공장·제품을 여럿이 함께 만들고 실제 물리처럼 시뮬레이션하는 플랫폼 |
| OpenUSD | 3D 장면을 담는 공통 파일 형식 (Omniverse의 기본 형식) |
| Isaac Sim | Omniverse 위에서 로봇, 컨베이어, 센서를 물리적으로 시뮬레이션하는 도구 |
| Isaac Lab | Isaac Sim 위에서 로봇이 스스로 동작을 배우게 하는(학습) 도구 |
| Sim-to-Real | 가상에서 학습·검증한 것을 실제 설비에 옮기는 것 |
| MuJoCo | 가벼운 물리 엔진. 브라우저에서도 돌아감. 로봇 셀 정밀 물리에 사용 (V3) |
| URDF | 로봇의 관절 구조를 적는 파일 형식. 로봇을 불러올 때 씀 |
| glb (glTF) | 웹에서 쓰는 3D 모델 파일 형식 |
| STEP / DXF | CAD 3D 파일 / CAD 2D 도면 파일 |
